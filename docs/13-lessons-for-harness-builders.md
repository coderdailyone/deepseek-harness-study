# 13 · 综合：给 agent harness 建造者的经验清单

> 本篇是全系列（01–12）的提炼，把 deepseek-harness 的做法压缩成可迁移的原则。每条后括号指向展开它的篇目。

## A. 关于状态与数据

**A1 · 让日志成为状态，而不是状态的记录。** 可变状态 + 事件通知的组合必然漂移；"日志即状态"让漂移在结构上不可能。检验标准是那条军规：凡进入模型请求的内容必须能从日志重建，且有运行时断言。（02）

**A2 · 把"能看见的"全部落盘：请求配置、收件箱、策略开关。** dsh 连 provider/model/system prompt 的变更（`request/header`）、未处理的用户输入（`agent/inbox/spliced`）、每会话沙箱模式（`sandbox/mode`）都是日志事件——重启恢复、审计、多会话隔离全部从回放免费获得。（02 / 03 / 08）

**A3 · 历史操纵走投影，不走变异。** 压缩 = 追加一条 replace 标记把旧区间遮蔽出投影；被遮蔽的事件永在日志里。`sourceEventSeqs` 强制每次替换点名它覆盖的每个事件——可验证、可回滚。（07）

**A4 · 崩溃恢复补关闭事件，永不截断。** 被打断的长自主运行含大量有效工作；合成错误结果 + interrupted 标记既保住工作又保住回放合法性。（02 / 03）

## B. 关于扩展与边界

**B1 · 扩展点 = 类型化事件，分发模式是契约的一部分。** waterfall（可改写可短路）/ serial（有序检查点）/ parallel（人人有份）/ emit（纯通知）各司其职；选错模式就是选错语义。（02）

**B2 · 能力 = 三角色接缝：契约、实现、消费面分开演化。** 换沙箱执行器不震动模型看到的工具 schema；指向远程沙箱时 bash/PTY/LSP 整组跟着走。但别预防性分包——第二个 provider 出现前保持单包。（02 / 06）

**B3 · 划清你不管的。** 沙箱只声明文件效果（网络诚实不管）；`confine(argv)` 只管同世界子进程（容器是整组 provider 替换，不是本接缝的后端）；Remote 只做一元调用（流不得伪装）。明说不管什么，和管什么一样重要。（08 / 11）

**B4 · 校验强度不随开发模式降级。** 源码启动的 SRC 回退给 Host 造弱描述符，但 Client 拒绝挂载它；热卸载严格端点不降级为推断。（11）

## C. 关于失败

**C1 · 事实与策略分离。** 失败载荷只携带事实（status、retry-after、request id），绝不带 `retryable` 裁决——"同一个 429 在交互组合该重试，在成本封顶批处理该拒绝"。（09）

**C2 · 一层拥有可见尝试。** 重试预算集中一层，SDK 层强制单次尝试（主动删掉库的重试配置）；每次重试都是日志里一个关闭的失败步骤 + 一条 retry 事件。多层隐藏重试相乘是灾难。（09）

**C3 · fail loud，fail closed。** 配置错误在加载时炸；没有可用沙箱后端抛 `SANDBOX_UNAVAILABLE` 而非静默无限制；审批服务缺席 = 拒绝。没有静默降级路径（我们跑通时被 node-pty 硬失败挡住,正是这条哲学的体验版）。（04 / 08）

**C4 · 预算绑在动作上，且防自激。** 后台完成唤醒空闲 agent 的预算（3 次）只由"认领用户亲笔消息"恢复——被唤醒的 turn 能启动新后台任务再唤醒自己，无人看管的自激链必须有不可自续的界。（05）

## D. 关于安全

**D1 · 让内核裁决，不做命令串预检。** 启发式读不懂展开/子进程/符号链接；"跑它，让内核决定"是唯一可信的拒绝信号。（08）

**D2 · 升权以真实拒绝为根据、一次一批、不持久化，且重试是新的被记录调用。** 同调用内自动重试 = 日志无法重建的隐藏重入。（08）

**D3 · 不宣传兑现不了的杠杆。** 升权字段按"是否挂载了受限执行器"门控出现——死杠杆制造注定失败的授权。同型：`enableRunInBackground` 关掉时参数从 schema 消失而非报错。（05 / 08）

**D4 · 委托的孩子权限在边界钉死。** 快照父策略种进孩子日志、审批钉 never（没人看提示）、父后续变化不追溯；并告诉孩子"范围已固定，缺权限就报告别重试"。（06）

## E. 关于工程过程（agent-first 的部分）

**E1 · 决策档案防重新扯皮，Alternatives considered 强制。** "没记录打败了谁的决策会招来 re-litigation"——683 篇笔记、生命周期路径编码、implemented 与现状同步、归档冻结。（01）

**E2 · 质量靠门禁不靠人盯。** 逐文件 100% 覆盖（不可测行书面自辩）、克隆检测、文档死链/字数/格式/翻译配对、类型粘贴与源码断言一致。人只做 review 和 polish，并对合并署名负责。（01）

**E3 · 验证世界，而非自我报告。** e2e 重新执行命令、外部重读文件、断言未触碰文件逐字节不变——"对 agent 自己输出做关键词探测会让作弊的 agent 通过"。postmortem 0003（agent 验证了另一个服务器）是反面教材。（10 / 12）

**E4 · 守卫要证明抓得住：引入回归、看红、撤销。** fail-before 是成文纪律。同族：mock 只到昂贵边界、真组合测试、构建产物冒烟。（10）

**E5 · 猎杀 AI 文风。** slop 清单（重复的家、变更叙述、状态标注、强调通胀）+ 专门清理"推理转录腔"的 skill，判据一句话：HEAD 处的读者不看任何会话记录能否验证每个引用。（01）

**E6 · 事故闭环到守卫。** 每篇 postmortem 都能指认它催生的具体规则/门禁/测试——事故不白出。（12）

## F. 三条最容易被低估的

**F1 · Twin 验证：** 中立契约在只有一个实现时是未验证的主张；两个内部结构刻意不同的真实现是最便宜的契约测试。（09）

**F2 · 常数带引证：** 重试次数/退避/抖动/空闲超时逐个标注同行实现的出处链接——后来者要改就得跟出处辩论。（09）

**F3 · 完成通知的投递车道按接收方状态选：** 忙碌 inject（多任务结算共享一步）、空闲唤醒、取消/排水中的绝不重开 turn（不把中断洗成模型请求、不在 teardown 上花钱）。这套三分车道在 jobs 与 subagent 结算两处独立收敛到同一形状——说明它是这个问题的自然解。（05 / 06）
