# 12 · 缺陷学：防御模式目录与四篇 postmortem

> 研究对象：deepseek-harness @ `47f9438`。依据：`docs/defensive-patterns.md`（33 行，七条规则）、`docs/postmortem/0001`–`0004`。

## 防御模式：七条从真实缺陷提炼的规则

文档开篇自我定位："每条模式都是一类**真的发布过或差点发布**的缺陷，以防止其复发的规则形式陈述。写生命周期、并发、子进程、teardown 代码前先读这个。"

**1. 正交结果各自独立上报。** 一个结果可以同时是几件事——进程可以超时 **且** exit 0（它捕获了信号）。`timedOut`/`signal`/`exitCode` 各自上报，"永不把一个标志的报告嵌在另一个的分支里，否则调用者把被掐断的运行读成干净成功"。

**2. 公共契约两侧都要兑现。** 实现收到同一结局的多种表示时，先归一化再穿出公共 API：适配器可以抛或发 error finish，但 `LlmRuntime.stream()` 只以终态 finish 块暴露模型请求失败——"让消费者不用猜捕到的异常来自 provider、包装器、chunk 记录还是自己的组装"。

**3. 异步状态不是同步状态。** `followup()` 没有逐消息的完成回执；后台任务完成与 turn 边界赛跑；几个排队的 follow-up 可以共享一个 `running` 区间。真要认领一次运行的调用方必须**显式定义自己的区间**（从消息的持久收件回执到下一次全 agent idle），并把选出的输出描述为"区间内的"而非"因果归于那条消息的"。反向的坑同样点名："等待的转换永不发生时，等待就挂死——'没有可等的东西'分支要显式处理。"

**4. Dispose 必须抵达静默，而非只是请求它。** 发出 kill/abort 就返回的 teardown 会留孤儿。清理必须 async 并 await 孩子退出，且**先关监听器/通知注册表再杀**——迟到的完成保持沉默。

**5. 在派发器里容错回调异常。** 用户提供的监听器抛出，不得 reject 它跑在其中的 promise、不得饿死后面的监听器。"一个坏订阅者永不打断核心生命周期。"

**6. 永不把环境变量或可预测路径交给不可信输出。** 子进程拿到擦洗过的 env（删 `*KEY*`/`*SECRET*`/`*TOKEN*`/`*PASSWORD*`），凭据不可能泄进输出或溢写文件；临时文件用 0700 私有目录 + 随机名 + 独占属主打开（`'wx'`, `0o600`）——"可预测的世界可读路径招来 symlink 竞态与泄露"。

**7. 链接形状的路径用 unlink 删。** `lstatSync().isSymbolicLink()` 然后 `unlinkSync`——unlink 只删链接且拒绝真目录，永不跟进目标；Windows 上递归 `rmSync` 可能穿过 junction 删进目标。"递归 rmSync 只留给已知的真目录。"

## 四篇 postmortem：为什么每层安全网都没拦住

Postmortem 的立项标准（01 篇讲过）：机制微妙 × 逃逸系统性 × 重发现昂贵。四篇的执行摘要浓缩：

**0001 · default export 吞掉 `inject`**：两个集成错误在满单元覆盖下弄崩 ACP——default export 让 Loader 丢弃 `inject`；traced 可选服务查找跨 shadow 边界失败。**手工挂载的测试把两条路径都绕过了**。修复=keyless 真 Loader 覆盖 + 插件导出的包规则。这篇直接催生了测试策略里"真组合测试"与"守卫要证明抓得住"两条纪律。

**0002 · 一个字面量对象永久禁用了文件系统工具**：`disabled: !!js ...` 表达式只在插件 `config` 里求值，别处它就是个 truthy 的原始表达式对象——文件系统栈从未启用过。更疼的是**第二层失守**：snapshot refresh 把 `UNKNOWN_TOOL` 结果当新期望接受了。修复=显式 overlay + 静态配置守卫 + snapshot 结果守卫。教训：刷新快照是评审动作，不是机械动作。

**0003 · Web agent 验证了另一个服务器**：agent 改了 GUI 源码但不知道自己的会话跑在哪个 URL/进程上；把裸 Vite 的 HTTP 200 当成功（尽管 `__DSH_BOOT__` 缺失白屏）；最后在另一个端口起了替代服务器去"验证"，而原页面早已吃到重建产物。修复=**把当前 URL 与运行模式做成模型可见、shell 可查**。这篇是"agent 操作真实系统"的经典失败样本：自我报告的成功 + 环境不可见 = 验证了错误的世界（与 10 篇"验证世界"呼应）。

**0004 · 良性通知行被当成启动器失败**：老 Landlock ABI 上启动器打一条良性 partial-enforcement 通知，harness 把"共享前缀 + 任意非零子退出码"当启动器失败——ripgrep 无匹配的 exit 1 变成 `SANDBOX_UNAVAILABLE`，且被 bash 承载的文件搜索又把结构化错误藏进 `SEARCH_FAILED`。修复=runner 分类改为**状态码门控的致命证据 + 精确的信息行排除**，文件搜索改走打包 ripgrep 不再穿沙箱 bash。教训：证据分类规则宽一分，良性输出就会污染成基础设施故障。

## 观感

这套"缺陷学"体系的价值在闭环：postmortem 记"为什么漏过"→ 规则进 defensive-patterns / testing.md / AGENTS.md → 门禁或测试钉住 → 下一个同类缺陷在写码时就被规则拦截。四篇 postmortem 每篇都能指认它催生的具体守卫——事故不白出。
